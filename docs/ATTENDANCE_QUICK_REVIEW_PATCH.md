# CenterPro — تحديث مراجعة الحضور وإضافة اليوم

أُعدّ الباتش الأصلي لنسخة `CenterPro-main (8).zip`، وطُبّق على آخر فرع `main` مع الحفاظ على تحديثات الحذف الآمن وتخطيط الآيباد.

## 1. تعديل الحالة من الجدول

- في صفحة تفاصيل يوم الحضور، أصبحت خانة «الحالة» قائمة منسدلة لكل موظف في جدول الكمبيوتر وبطاقات الهاتف.
- اختيار «حاضر» أو التحويل إلى «غير محسوم» من غير تسجيل حضور سابق يحفظ مباشرة، دون فتح نافذة «مراجعة».
- عند اختيار «حاضر» دون وجود وقت سابق، يتم تسجيل **وقت بدء الدوام المحدد لذلك اليوم** كوقت حضور يدوي، ويضاف تنويه «تسجيل سريع بوقت بدء الدوام» إلى ملاحظة السجل. لتعديل الوقت الفعلي، استخدم زر «مراجعة» الذي بقي كما هو.
- إذا كان الموظف مسجلاً «حاضر» واخترت «غير محسوم»، يجب تأكيد إزالة التسجيل عبر النافذة المعتادة قبل الحفظ.
- اختيار «غياب بعذر»، «غياب بدون عذر»، أو «مستثنى / لا يوجد دوام» يفتح نافذة «مراجعة» بالحالة المختارة مسبقاً. لا تُحفظ الحالة حتى تُكمل المراجعة وتضغط «حفظ التعديل»، وبإمكانك كتابة سبب أو ملاحظة.
- السجلات المقفلة بسبب أرشفة الشهر تبقى للعرض فقط، والشهر المعاد فتحه يخضع لنفس صلاحيات وأمان الرواتب السابقة.
- كل حفظ يمر عبر نفس واجهة `updateData` والقواعد والتحقق على السيرفر وسجل العمليات، ولا توجد كتابة مباشرة لقاعدة البيانات من القائمة المنسدلة.

## 2. إنشاء يوم الحضور

- الوقت الافتراضي لليوم **الجديد فقط** هو `15:00:00` (3:00 PM).
- تغيّر التاريخ أو الوقت **قبل أول حفظ** لا يُعدّ تعديلاً ولا يظهر حقل «سبب التعديل»؛ أصلحنا التحقق في الواجهة والسيرفر.
- إذا كان اليوم موجوداً مسبقاً وتغيّرت إعداداته، يظهر سبب التعديل ويصبح إلزامياً. دون تغيير فعلي لا يُتاح حفظ تعديل وهمي.
- أوقات الأيام السابقة لا تُمس. إعادة احتساب تأخر الموظفين عند تعديل وقت يوم محفوظ تبقى كما كانت.
- منع الأيام المتكررة أو فتح أكثر من يوم بنفس الوقت وحماية أشهر الرواتب المؤرشفة باقٍ دون تغيير.

## 3. الملفات الرئيسية

- `src/components/attendance/day-detail.tsx` — القائمة السريعة وتوحيد حفظ السجل.
- `src/lib/attendance-quick-review.ts` — توجيه الحالة ووقت الحضور اليدوي السريع.
- `src/components/attendance/day-dialogs.tsx` — وقت 3 PM والسبب عند التعديل الفعلي فقط.
- `src/server/domain.ts` — عدم إلزام السبب عند الإنشاء الأول حتى للتاريخ السابق.
- `src/components/attendance/attendance.module.css` — تخطيط القائمة المتجاوب.
- `tests/domain/attendance-quick-review.test.ts` و`tests/domain/server-domain.test.ts` و`tests/e2e/attendance.spec.ts` — اختبارات السلوك والتحقق من الحماية.

## 4. التشغيل والتحقق

لا توجد هجرة SQL مطلوبة. قبل النشر تأكد من أخذ نسخة احتياطية، ثم نفّذ في بيئة Node.js 24.x:

```bash
npm ci
npm run lint
npm run typecheck
npm test
npm run build
npm run test:e2e -- tests/e2e/attendance.spec.ts
```

تغطي اختبارات الإصدار الحفظ السريع، تأكيد إزالة الحضور، إلغاء مراجعة الغياب والاستثناء دون حفظ، المشاركة الفردية، ووقت اليوم الجديد. تشمل اختبارات السيرفر حماية الأرشيف والأشهر المعاد فتحها والرواتب بعد الصرف، وتشمل اختبارات المتصفح الحفظ المعلّق وفشل الاتصال وتعارض التعديلات بين جهازين.

تلتف قائمة الحالة داخل بطاقة الهاتف عند ضيق المساحة. تستخدم مراجعة السجل وتأكيد الإزالة نافذة واحدة مع الاحتفاظ بالمسودة، حتى يبقى التأكيد قابلاً للوصول ويظهر خطأ الحفظ دون فقدان الملاحظات أو تجاوز حماية تعارض التعديلات.

تُشغّل فحوصات `lint` و`typecheck` وVitest والبناء واختبارات Playwright محلياً، ثم يشغّل مسار `CenterPro quality` المجموعة الكاملة على نفس commit قبل نشر Production. لا يحتاج التحديث إلى متغيرات بيئة جديدة.
