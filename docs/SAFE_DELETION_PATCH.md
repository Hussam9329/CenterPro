# CenterPro — الحذف الآمن للسجلات

دُمج باتش الحذف الآمن في مشروع CenterPro المتصل بـ Neon. يعمل على الجداول الحالية داخل نظام المعاملات، ولا يحتاج ترحيل قاعدة بيانات أو متغيرات بيئة إضافية.

## السجلات المشمولة

- الموظفون وحساباتهم، والأقسام.
- أيام الحضور وسجلات حضور الموظفين.
- الخصومات والمكافآت.
- أشهر الرواتب المؤرشفة وعمليات صرف الرواتب.
- مواسم التقييم والدورات والامتحانات وتقييمات المصححين.

## ماذا يحدث عند الحذف؟

- يعرض النظام معاينة بعدد السجلات التابعة التي ستُحذف، وأثر العملية، وأسباب منعها إن وجدت.
- يلزم **سبب حذف** (ثلاثة أحرف على الأقل)، وكتابة كلمة **«حذف»** في عمليات الحذف الرئيسية أو المتسلسلة.
- لا يُرسل المتصفح السجلات المراد حذفها كأوامر تنفيذ؛ **السيرفر يعيد بناء خطة الحذف بنفسه** من بيانات قاعدة البيانات، داخل معاملة تحمي من التعارض.
- حذف يوم حضور يحذف سجلات ذلك اليوم؛ حذف موسم يحذف دوراته وامتحاناته وتقييماته؛ حذف دورة يحذف امتحاناتها وتقييماتها؛ حذف امتحان يحذف تقييماته.
- حذف موظف يحذف سجلاته غير المحمية، واستثناءاته في أيام الحضور، ويلغي بيانات الدخول وجلساته. لا يمكن حذف آخر حساب مشرف عام أو الحساب الذي يستخدمه المشرف حالياً.
- تبقى سجلات التدقيق القديمة محفوظة، وتُضاف إليها عمليات حذف مفصلة مع اسم المنفّذ والتاريخ والسبب.
- تحديث الرواتب والإحصائيات الحية يأتي من البيانات الجديدة، بدون تغيير صيغة الرواتب أو معادلة النقاط.

## حدود الحماية

- يُمنع حذف يوم حضور أو سجل حضور لشهر **مؤرشف، معاد فتحه، أو له صرف راتب مسجّل**.
- يُمنع حذف موظف مرتبط براتب مصروف أو بتاريخ رواتب محمي أو تدقيق تابع لدورة مؤرشفة.
- يُمنع حذف قسم مرتبط بموظفين أو مستخدم بأيام الحضور؛ يجب معالجة ارتباطاته أولاً.
- يُمنع حذف تقييم منفرد لامتحان مغلق، وامتحان ضمن دورة مؤرشفة، ودورة ضمن موسم مؤرشف؛ يمكنك حذف الأب بالكامل بتأكيد مستقل.
- حذف أرشيف شهر معه عمليات صرف يحتاج إزالة قيود الصرف أولاً بتأكيد منفصل. حذف *قيد الصرف* لا يلغي تحويل الأموال الحقيقي.
- حساب الموظف لا يستطيع إدارة حذف الرواتب أو الموظفين؛ المدقق يستطيع حذف سجل تقييم مصحح ضمن دورة وامتحان مفتوحين فقط.
- حذف الخصومات والمكافآت في شهر معاد فتحه متاح للمشرف العام فقط، وتستلزم الأرقام المؤرشفة المعاد فتحها مراجعة وإعادة احتساب صريحة وفق سير العمل الحالي.

## استخدام الواجهات

- زر الحذف موجود بجوار السجل في الموظفين والأقسام والحضور والخصومات والمكافآت.
- حذف قيد صرف متاح داخل تفاصيل راتب الموظف، من قسم «سجل الصرف». حذف أرشيف الشهر متاح للمشرف العام من صفحة الرواتب.
- تظهر أزرار الحذف في الموسم والدورة والامتحانات وإدخالات المدققين، وفق صلاحية الحساب وحالة الأرشيف.
- حذف تقييم من واجهة المدقق ينتظر انتهاء الحفظ التلقائي. تفريغ حقل رقمي يظل تعديلاً؛ إزالة السجل نفسه تحتاج سبب الحذف والتأكيد. لا يُحتسب السجل الفارغ تماماً كامتحان مقيّم.
- عند فشل الطلب يبقى السبب والتأكيد للمراجعة والمحاولة مجدداً. عند تعارض نسخة البيانات، أغلق نافذة التأكيد وراجع البيانات الجديدة ثم افتحها من جديد.

خذ نسخة احتياطية قبل تفعيل الحذف في بيئة الإنتاج. اختبارات الحذف تعمل على بيانات اختبار معزولة، ولا تُجرى على سجلات الإنتاج.

## فحص القبول المقترح

1. أنشئ يوم حضور تجريبياً وسجّل فيه عدة موظفين؛ احذفه، وتأكد من اختفاء سجلاته وعدم تأثر أيام أخرى.
2. حاول حذف يوم حضور ضمن شهر مؤرشف أو له صرف؛ يجب رفض الحذف برسالة مفهومة.
3. أنشئ موسم ثم دورة ثم امتحان مع تقييم؛ تأكد من أعداد المعاينة، ثم حذف الامتحان وإعادة إنشائه، ثم الدورة، ثم الموسم.
4. حاول حذف دورة داخل موسم مؤرشف أو امتحان داخل دورة مؤرشفة؛ يجب رفض الحذف الجزئي.
5. جرّب حذف موظف تجريبي بلا سجل صرف، وتأكد من انتهاء جلساته ورفض تسجيل دخوله.
6. جرّب حذف موظف لديه سجل صرف؛ يجب المنع. جرّب حذف قسم مرتبط بموظفين؛ يجب المنع.
7. تأكد من حفظ سبب كل عملية، وأن السجل التاريخي لا يُمحى بالحذف.
8. تأكد أن حساب الموظف العادي لا يرى حذف الأجزاء الإدارية، وأن المدقق لا يستطيع حذف تقييم دورة مغلقة.
9. بعد كل حذف مسموح، راجع كشف الراتب ونقاط التقييم للتأكد من احتساب البيانات المتبقية بشكل صحيح.

## التحقق الآلي

تغطي اختبارات Vitest قواعد الحذف والصلاحيات ومنع تجاوز التأكيد عبر أوامر الحذف القديمة. تختبر حالات PGlite مسار API الحقيقي والمعاملات والمفاتيح الخارجية وإلغاء بيانات الدخول والجلسات والتراجع الكامل عند الفشل. تختبر Playwright النوافذ على الكمبيوتر والهاتف، والحفظ التلقائي، وفشل الاتصال، والتعارض، وعدم إرسال سلسلة الحذف من المتصفح.

```bash
npm run check
npm run test:e2e
# بعد بناء نسخة باعتمادات اختبار وهمية للخادم:
npm run test:e2e:remote
```

يشغّل GitHub Actions الفحوصات والبناء واختبارات المتصفح المحلية والمتصلة لكل commit على `main` قبل النشر.
